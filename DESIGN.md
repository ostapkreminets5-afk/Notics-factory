# Noctics Factory — дизайн проєкту

Noctics Factory — десктопна студія, яка веде гру від одного текстового промпту до готових білдів для Windows, macOS, Linux, Web, Android та iOS. Усю творчу й інженерну роботу виконує **AI-ядро** — локально встановлений Claude Code CLI, підключений до підписки Claude. Студія планує роботу, ставить задачі в черги, зберігає результати, показує прогрес і збирає фінальні білди.

## 1. Стек

| Шар | Технологія |
|---|---|
| Оболонка | Tauri 2 (безрамкове вікно, власний титлбар) |
| Інтерфейс | Dioxus 0.7, Rust → WebAssembly |
| Бекенд | Rust (edition 2024) |
| Сховище | SQLite через `rusqlite` (bundled) |
| Паролі | Argon2 |
| HTTP | `ureq` (запити лімітів підписки) |
| AI | Claude Code CLI, модель `claude-opus-5-5` |

## 2. Структура репозиторію

```
Noctics-factory/
├── Cargo.toml          workspace + крейт інтерфейсу (noctics-factory-ui)
├── Dioxus.toml         налаштування dx (web, out_dir = dist)
├── src/                інтерфейс (Dioxus → wasm)
├── src-tauri/          бекенд і десктопна оболонка (noctics-factory)
├── shared/             спільні типи для обох боків (noctics-shared)
└── assets/
    ├── fonts/          Unbounded, Manrope, JetBrains Mono (latin + cyrillic)
    └── styles/         CSS за розділами
```

### Запуск і збірка

| Команда | Що робить |
|---|---|
| `cargo tauri dev` | запускає `dx serve --port 1420` і відкриває вікно Tauri |
| `cargo tauri build` | `dx bundle --release` → `dist/public`, потім інсталятор |
| `cargo check --workspace` | перевірка бекенду й shared |
| `cargo check -p noctics-factory-ui --target wasm32-unknown-unknown` | перевірка інтерфейсу |

## 3. Архітектура

```
┌──────────────────────── Вікно Tauri ────────────────────────┐
│  Інтерфейс Dioxus (wasm)                                    │
│   App → AuthScreen | Workspace → розділи                    │
│        │ invoke(команда)          ▲ події                   │
└────────┼──────────────────────────┼─────────────────────────┘
         ▼                          │ studio-changed / builds-changed
┌──────────────────────── Бекенд Rust ────────────────────────┐
│  commands  studio_commands  build_commands  ...             │
│     │            │                │                         │
│  Accounts     Studio ──────► Builder                        │
│  Skills       (черга, 2 воркери)  (генерація коду + білди)  │
│  Toolbox        │                 │                         │
│  Artifacts      ▼                 ▼                         │
│  Pinterest    ClaudeCode CLI    Claude Code агент + рецепти │
│                                                             │
│  SQLite: accounts / skills / studio / toolbox / builds /    │
│          artifacts                                          │
└─────────────────────────────────────────────────────────────┘
```

**Принципи**

- Інтерфейс нічого не обчислює сам. Він викликає Tauri-команди й перечитує дані, коли бекенд надсилає подію про зміну.
- Довгі задачі не блокують команди: команда лише ставить задачу в чергу (SQLite), а воркери її виконують.
- Після перезапуску незавершені задачі (`generating`) повертаються в `queued` і доробляються.
- Типи, статуси й помилки описані один раз у `shared` і серіалізуються однаково на обох боках.

## 4. Життєвий цикл гри

```
Вхід → Промпт + рушій + платформи → План і референси → Pinterest → Навички + Екрани Claude Design → Код гри + ассети ComfyUI → Плейтест → Білди
```

1. **Вхід.** Локальний акаунт (ім’я, email, пароль від 8 символів). Сесія відновлюється при запуску.
2. **Промпт.** Опис гри (12–4000 символів), рушій і платформи білду.
3. **План.** Claude повертає JSON за схемою: назва, пітч, дизайн-документ, стиль (палітра з 5 кольорів, шрифти, радіус кутів до 32 px, настрій), 3–8 екранів і 10–24 референси за темами: світ, персонажі, стиль 3D-персонажів, світло, VFX, VFX-спрайти, інтерфейс, головні меню, панелі, кнопки, іконки, матеріали, предмети, анімація, звуки, музика. Вісім тем шукаються в Pinterest і на ArtStation для кожної гри обов’язково: персонажі, стиль 3D-персонажів, інтерфейс, головні меню, панелі, кнопки, VFX і VFX-спрайти. Якщо Claude пропустив якусь із них, ядро саме додає пошук з ігровим уточненням (`game main menu screen ui`, `vfx sprite sheet animation`, `stylized 3d game character render`…) і темою світу гри.
4. **Pinterest.** Для візуальних тем прихований webview шукає піни. Звуки й музика — текстові референси: теги звучання для ComfyUI.
5. **Навички.** Кожна увімкнена навичка пише свій документ-результат.
6. **Екрани.** Claude Design малює кожен екран як HTML 1280×720 за дошкою референсів. Арт на екранах — слоти з промптом, не фігури. Екран можна виправити коментарем, перегенерувати або апрувнути.
7. **Код гри й ассети.** Щойно всі навички й екрани готові, Claude-агент сам починає писати гру під обраний рушій і генерує арт, VFX, UI, звуки й музику через ComfyUI API Noctics за референсами відповідних тем. Запускається один раз на проєкт; далі — вручну зі сторінки збірки.
8. **Плейтест.** Бот студії грає в гру й знімає кадри, Claude порівнює їх із затвердженими екранами, виправляє знайдене, і бот проходить гру ще раз (див. розділ 11). Поки лише для Godot; для інших рушіїв етап пропускається з записом у журналі.
9. **Білди.** Після плейтесту студія сама ставить білди під платформи з промпту. Платформу без потрібних інструментів пропускає й пише про це в журнал.
10. **Формування.** За бажанням проєкт отримує фінальну назву та обкладинку — один з апрувнутих екранів.

### Статуси

| Об’єкт | Статуси |
|---|---|
| Проєкт | `queued` → `planning` → `designing` → `ready`, або `failed` |
| Екран | `queued` → `generating` → `draft` → `approved`, або `failed` |
| Результат навички | `queued` → `generating` → `done`, або `failed` |
| Код гри | `generating` → `ready`, або `failed` |
| Плейтест | `capturing` → `reviewing` → `capturing` → `done`, або `failed` |
| Білд | `queued` → `running` → `done` / `failed` / `cancelled` |

## 6. AI-ядро (Claude Code)

### Пошук і підключення

- `claude.exe` шукається в `PATH` і в `~/.local/bin`.
- Стан підключення: `claude --version` і `claude auth status`. Ядро вважається підключеним лише при вході через підписку claude.ai.
- `ANTHROPIC_API_KEY` і `ANTHROPIC_AUTH_TOKEN` прибираються з оточення, щоб робота йшла через підписку, а не API-ключ.
- Вхід запускається командою `claude auth login` в окремому вікні консолі.
- Ліміти підписки (5-годинне і тижневе вікно) читаються з OAuth-облікових даних Claude Code.

### Два режими виклику

| Режим | Де | Параметри |
|---|---|---|
| Відповідь | план, навички, екрани, референси | `-p --output-format json --tools "" --safe-mode --no-session-persistence --strict-mcp-config`, system prompt з тимчасового файлу, за потреби `--json-schema`; тайм-аут 20 хв |
| Агент | код гри | `--output-format stream-json`, інструменти `Read, Write, Edit, Glob, Grep, Bash`, `--permission-mode acceptEdits`, робоча папка — `source/`, бриф через `--add-dir`; тайм-аут 2 год |

Зусилля: `high` для плану, нових екранів і навичок етапу 01; `medium` для правок, референсів і пізніших навичок.

### Обробка помилок

Відповідь CLI розбирається в типізовані помилки: ліміт підписки, rate limit (429), перевантаження (503/529), вихід з акаунта (401/403), відмова, обрізана відповідь, порожня відповідь. Кожна має людський текст в інтерфейсі.

### Черга студії

- Задачі трьох типів: `Plan`, `Output` (навичка), `Screen`.
- До 2 воркерів одночасно. Кожен перед стартом перевіряє підключення Claude і зупиняється, якщо його немає.
- Після кожної задачі надсилається `studio-changed`, а в журнал пишеться подія.

## 7. Навички (SKILLS)

- Навичка — це інструкції для ядра з номером етапу (1–6), назвою, описом, категорією й прапорцем «увімкнено».
- Сім стартових навичок створюються при першому запуску. Свої можна додавати, редагувати, вимикати й видаляти.
- Навички також експортуються в папку `skills/` у даних програми.
- `game-ui-screens` працює не як окремий документ, а як system prompt для генерації екранів.
- «Синхронізувати» додає в проєкт навички, увімкнені після планування.
- Навички етапу 06 «Збірка» (наприклад «Скрипти гри», «Преміальні VFX-ефекти») не пишуть окремого документа: однією відповіддю вони не встигали за 20-хвилинний ліміт і блокували код. Тепер їхні інструкції лягають у бриф агента як `build-skills/NN-<навичка>.md`, і агент виконує їх прямо в коді гри. «Синхронізувати» / «Продовжити» прибирає незавершені записи етапу 06 у старих проєктах і, якщо екрани й інші навички готові, одразу запускає агента коду.

## 8. Claude Design

- Сторінка проєкту з екранами, документами навичок, стилем і референсами.
- Екрани — самодостатні HTML-документи 1280×720 у палітрі й шрифтах проєкту.
- **Стиль виводиться зі світу гри.** У плані Claude спершу пише `look` — як світ виглядає в кадрі: світло й час доби, погода, матеріали панелей і рамок, орнаменти, кольори героя, ворогів, загрози й надії. Потім бере з цього опису 5 кольорів у ролях «фон», «поверхня панелей», «колір світу», «текст», «акцент головної дії» і до кожного пише джерело — конкретну річ цього світу. Насиченість — така, як у світі, без правила «завжди яскраво» чи «завжди приглушено». Стилі інших ігор студії Claude бачить, щоб не переносити їх за звичкою.
- Палітра з джерелами кольорів і `look` показуються в стилі гри (Claude Design, Pinterest, вузол «План гри») і йдуть у кожен запит на екран. Екранам заборонено загальний набір «темної гри» (місяць, туман, жарини, віньєтка, зерно, рядок підказок клавіш), якщо його не просить світ.
- **Новий стиль і екрани** (`restyle_project`) — Claude заново виводить стиль з промпту, дизайн-документа й дошки референсів, а всі екрани гри стають у чергу й перемальовуються без старого екрана-зразка.
- Дії: додати екран, виправити за коментарем (до 2000 символів), перегенерувати, апрувнути, вибрати обкладинку, сформувати проєкт.
- Окремо збираються **артефакти** claude.ai: студія кожні 15 секунд переглядає транскрипти Claude Code в `~/.claude/projects` за останні 30 днів і додає посилання на власні артефакти. Вони відкриваються в окремому вікні.

### Open Design — інші дизайни й варіації

Паралельно з Claude Design студія віддає ті самі екрани в [Open Design](https://open-design.ai) — open-source робочий простір дизайну, який працює через Claude Code. Він робить інші дизайни й варіації кожного екрана у своїй дизайн-системі, зі справжнім артом (стокові фото, а не фігури з коду).

- Потрібен встановлений Open Design (`%LOCALAPPDATA%\Programs\Open Design`). Вікно застосунку не відкривається: студія сама запускає його демон без вікна через `Open Design.exe` у режимі Node (`ELECTRON_RUN_AS_NODE=1`, `daemon-cli.mjs --no-open --port 47840`). Дані лежать окремо — у `<дані програми>/open-design/`.
- Старт — щойно Claude склав план гри, або вручну: «Згенерувати в Open Design» / «Ще варіації» на сторінці Claude Design і у вузлі «Варіації дизайну». Якщо Pinterest чи ArtStation ще шукають референси цієї гри, раунд чекає на них до 6 хвилин (статус «Чекає референси»).
- **4 варіації на екран — по одній на джерело:**

| Код | Джерело | Що отримує агент |
|---|---|---|
| `prompt` | Промпт | лише промпт, план і стиль гри |
| `pinterest` | Pinterest | до 12 пінів з дошки (`736x`) |
| `artstation` | ArtStation | до 12 робіт з дошки (`medium`) з авторами |
| `mix` | Pinterest + ArtStation | обидві дошки разом |

- Перед кожним раундом студія завантажує картинки дошки в `<проєкт Open Design>/noctics-references/{pinterest,artstation}/` (до 6 МБ на файл). Спершу йдуть теми інтерфейсу (інтерфейс, меню, панелі, кнопки, іконки), далі по одній картинці з кожної теми по колу. Бриф перелічує файли з темою й назвою, агент переглядає їх інструментом Read; вставляти їх в екрани заборонено — це лише орієнтир стилю.
- Джерело без картинок пропускається: без пінів — немає `pinterest` і `mix`, без робіт ArtStation — немає `artstation` і `mix`. Пропущені джерела показуються жовтою приміткою.
- Кожен раунд: проєкт Open Design `<гра> · Noctics` з навичкою `frontend-design`, бриф зі стилем гри та списком екранів (до 8), файли `screen-NN-<джерело>-<раунд>.html`. Старі файли без коду джерела (`screen-NN-<літера>.html`) вважаються варіаціями «Промпт». Дизайн-система підбирається за настроєм гри (`fantasy`, `neon`, `cosmic`, `retro`, `futuristic`, `hud`, `doodle`, `vintage`, інакше `dramatic`), а кожен наступний раунд бере інший напрям.
- Студія стежить за всіма запусками проєкту (стратегія Open Design сама робить кілька кроків) і вважає раунд завершеним, коли 15 секунд немає активних запусків. Ліміт раунду — 3 години. Після перезапуску програми раунд, що ще чекав на референси, стартує заново.
- На сторінці й в інспекторі вузла варіації фільтруються чипами за джерелом, кожна картка має мітку джерела.
- Превʼю — через `GET /api/projects/<id>/export/<файл>?inline=1` демона: HTML з уже вбудованими картинками й шрифтами. Варіацію можна відкрити в браузері або в папці проєкту.

## 9. Pinterest і ArtStation

Claude розбирає промпт гри й складає дошку референсів: для кожної візуальної теми є англійський пошуковий запит. За цими запитами ядро підтягує картинки з обох джерел на одну дошку стилю. Назви знайдених пінів і робіт потрапляють у бриф Claude для екранів і навичок.

### Pinterest

- Вхід через окреме вікно з pinterest.com. Сесію визначає кука `_auth`.
- Для кожного референсу прихований webview шукає піни за запитом і збирає зображення.
- Локальний HTTP API на `127.0.0.1:47821` (лише GET):
  - `/` — довідка;
  - `/health` — чи працює API і чи є вхід;
  - `/pins?q=<запит>&limit=<1-100>` — піни з пошуку.

### ArtStation

- Вхід не потрібен. Пошук іде напряму через JSON-пошук ArtStation (`/api/v2/search/projects.json`): спершу береться CSRF-токен і його cookie, далі сторінки по 50 робіт. Сесія живе 20 хвилин і оновлюється сама, коли ArtStation її відхиляє.
- Роботи 18+ відсіюються. На дошці — мініатюри 400×400 (`smaller_square`), у перегляді — `medium`, кнопка веде на сторінку роботи.
- На кожен референс — до 8 робіт. Пошук запускається, коли Claude підбирає дошку, і на старті програми для референсів без робіт. Вручну — «Оновити ArtStation».
- Локальний HTTP API на `127.0.0.1:47833` (лише GET):
  - `/` — довідка;
  - `/health` — чи працює API;
  - `/artworks?q=<запит>&limit=<1-100>` — роботи з пошуку: `id`, `title`, `author`, `image`, `image_large`, `link`.

Обидва API приймають запити лише з цього комп’ютера й відповідають CORS тільки сторінкам з localhost.

## 10. ComfyUI — усі моделі на одну задачу

Розділ ComfyUI бере одну задачу й проганяє її через **кожну** встановлену модель локального ComfyUI (`127.0.0.1:8188`), щоб порівняти результати поруч у галереї.

### Типи ассетів

| Тип | Моделі | Що виходить |
|---|---|---|
| Концепт-арт, текстура, VFX-ефект | усі моделі зображень | PNG; текстура показується плиткою 2×2, ефект — на чорному тлі |
| Спрайт, UI-елемент | усі моделі зображень + BiRefNet | PNG з прозорим тлом |
| 3D-модель | найкраща модель зображень малює референс → усі 3D-моделі | GLB з текстурою, обертається прямо в картці |
| Музика, звук | усі аудіомоделі | FLAC з плеєром |

### Моделі

- Список моделей стежить за ComfyUI постійно: стан сервера перевіряється кожні 4 с, список моделей — кожні 15 с. Коли ComfyUI працює, Noctics читає `/object_info` (файли й вузли), коли вимкнено — сканує папку `models/` встановленого ComfyUI.
- Знайомі родини: Z-Image (Turbo), FLUX.2 Klein 4B/9B, будь-який SD/SDXL-чекпойнт, ACE-Step 1.5 (AIO, XL SFT/Turbo/Base, 2B), Stable Audio Open, TRELLIS.2, Pixal3D. Для кожної Noctics перевіряє супутні файли (text encoder, VAE, DINO, BiRefNet, MoGe) і потрібні вузли; чого бракує — показує в списку.
- Кожну модель можна вимкнути з порівняння перемикачем — на сторінці або в перемикачі ⇅ біля вкладки.

### Як іде задача

```
Задача + типи → Claude пише промпт (JSON за схемою) → черга GPU → кожна модель по черзі → файли в галерею
```

1. Для кожного вибраного типу створюється задача з запуском на кожну увімкнену модель. Усі моделі отримують той самий сид.
2. AI-ядро пише промпт англійською з правилами типу (прозоре тло, безшовність, чорне тло, A-поза для 3D, теги для аудіо) і стилем вибраної гри. Без Claude промпт складається з опису.
3. Один воркер по черзі відправляє графи в ComfyUI, між різними родинами моделей звільняє VRAM, стежить за `/history`, забирає результати через `/view` у `<дані програми>/comfy-gallery/<задача>/`.
4. Якщо ComfyUI зупинився — задача повертається в чергу і продовжується, щойно він знову з’явиться. Кнопка «Запустити ComfyUI» стартує встановлений ComfyUI (`python main.py --listen 127.0.0.1 --port 8188`).

### Локальний API для Claude Code

Сервер на `127.0.0.1:47822` (або наступний вільний порт):

- `GET /` — довідка; `GET /models` — моделі; `GET /tasks`, `GET /tasks/<id>` — задачі з файлами;
- `POST /tasks` — нова задача: `{"kind": "sprite", "brief": "…"}`, `kinds` або `"all"`; з полями `prompt`/`tags` Claude не викликається;
- `GET /files/<задача>/<файл>` — файли галереї (з `Range`), `GET /vendor/model-viewer.min.js` — переглядач 3D.

Приймає лише локальні запити; POST — лише `application/json`.

## 10а. Пошук ассетів — готові ассети з інтернету

Розділ «Пошук ассетів» (і вузол з тією ж назвою) шукає готові ассети під конкретну гру на itch.io, OpenGameArt, Kenney, Quaternius, Poly Pizza, Poly Haven, ambientCG, Freesound, Pixabay, Google Fonts; платні — на itch.io, GameDev Market, CraftPix, Unity Asset Store і Fab, лише коли вони набагато влучніші.

```
План гри + дошка референсів → Claude (WebSearch, WebFetch) → JSON за схемою → перевірка посилань → прев’ю og:image → картки
```

1. Пошук стартує сам, щойно Claude склав план гри. Для старих проєктів — кнопка «Знайти ассети».
2. Claude отримує назву, пітч, промпт, рушій, стиль, екрани, дизайн-документ і дошку референсів і повертає 8–24 знахідки: назва, сторінка, категорія, автор, ліцензія, ціна (`free`, `pay_what_you_want`, `paid`) і чому пасує.
3. Студія лишає тільки справжні `http(s)`-сторінки без дублікатів, сама читає з кожної `og:image` для прев’ю і пише в журнал «Claude знайшов в інтернеті N готових ассетів».
4. Поле «Що шукати окремо» (до 300 символів) звужує пошук: нові знахідки додаються до наявних (до 48), без поля — повний новий підбір.
5. Перед генерацією коду знахідки лягають у бриф як `found-assets.md`. Агент може завантажити безкоштовні з відкритою ліцензією й пише автора, сторінку й ліцензію в `CREDITS.md`; платні — лише орієнтир стилю.

Виклик Claude — режим «Відповідь» з інструментами `WebSearch,WebFetch` (`--allowedTools`, `--permission-mode dontAsk`). Один пошук за раз; після перезапуску незавершений пошук повертається в чергу.

## 10б. Mixamo — анімації персонажів

Розділ «Mixamo» і вузол «Анімації» беруть анімації скелета з mixamo.com і запікають їх у FBX для гри.

```
Замовлення (агент / ти / набір під гру) → пошук на Mixamo → найближча анімація → запікання на персонажі → FBX у бібліотеці → агент копіює в гру й допрацьовує
```

- **Вхід.** Окреме вікно mixamo.com, вхід через Adobe. Noctics читає `access_token` з `localStorage` сайту. На старті прихований webview перечитує токен сам; токен, який Mixamo відхилив (401/403), більше не береться, а замовлення чекають у черзі до нового входу.
- **Парсер.** Каталог Mixamo (`/api/v1/products`, лише `Motion`) ранжується за схожістю з запитом: збіг слів у назві й описі, префікси (`run` → `Running`), точна назва, покриття всіх слів, штраф за зайві слова.
- **Набір під гру.** «Підібрати під гру» розбирає промпт, пітч і дизайн-документ: базово idle, walk, run, jump, hit, death; за словами жанру додає удари мечем, стрільбу, закляття, бійку, стелс, лазіння, плавання, зомбі, танці. Ходьба й біг — «на місці».
- **Запікання.** Деталі анімації (`gms_hash`) → `POST /api/v1/animations/export` з персонажем Mixamo (основний персонаж акаунта або Y Bot), налаштуваннями «на місці», «дзеркально», обрізання у відсотках, fps 24/30/60, зі скіном чи без → `GET /characters/<id>/monitor` до `completed` → FBX з `job_result` у `<дані програми>/mixamo-library/project-<id>/`.
- Один воркер, замовлення по черзі. Повтор того самого замовлення повертає наявне. Після перезапуску незавершені знову стають у чергу.
- **Агент.** Якщо Mixamo підключено і рушій 3D, Claude-агент отримує правила: `/plan` на старті, `/order` для інших анімацій, копіювання FBX у гру, цикли, блендинг у стейт-машині, швидкість під рух, вимкнений кореневий рух для in-place кліпів, події кроків і влучань. Для Godot — AnimationPlayer + AnimationTree, Unity — Playables API, Three.js — FBXLoader + AnimationMixer, glTF-рушіям — конвертація через Blender. Phaser і Defold анімації скелета не отримують.

### Локальний API для Claude Code

Сервер на `127.0.0.1:47834` (лише GET):

- `/` — довідка; `/health` — чи підключено Mixamo і який персонаж;
- `/search?q=<запит>&limit=<1-100>` — анімації, відсортовані за схожістю;
- `/order?name=&q=&id=&project_id=&in_place=1&mirror=1&skin=1&fps=30&trim=10-90` — замовлення; без `id` Noctics сам бере найближчу до `q`;
- `/plan?project_id=` — набір під гру; `/animations?project_id=`, `/animations/<id>` — стан і шлях до FBX (`file`).

## 11. Збірка

### Папки гри

```
Документи/NocticsFactory/<назва>-<id>/
├── source/            код гри
├── builds/            готові білди
└── .noctics/
    ├── brief/         матеріали для агента
    │   ├── design.md
    │   ├── references.md
    │   ├── found-assets.md
    │   ├── skills/NN-<навичка>.md
    │   └── screens/NN-<екран>.html
    ├── playtest/run-<час>/
    │   ├── round-1/   кадри першого прогону бота + manifest.json
    │   ├── round-N/   прогони, які Claude запускав сам
    │   ├── final/     фінальний прогін після виправлень
    │   ├── verdict.json
    │   ├── godot.log
    │   └── review.log
    └── generation.log
```

Код гри можна згенерувати або підключити наявну папку проєкту. Студія перевіряє маркер рушія (`project.godot`, `.uproject`, `Cargo.toml`, `package.json`, `game.project` тощо).

### Генерація коду

- Перед стартом бриф перезаписується з актуальних даних проєкту.
- Агент отримує правила: інтерфейс повторює апрувнуті екрани; гра повна (меню, основний цикл, перемога/поразка, пауза, гучність); клавіатура, миша, геймпад і сенсор; повністю офлайн; без заглушок.
- Для кожного рушія є свій контракт (наприклад, Unity запускає гру з коду без ручних сцен, Rust-рушії мають збиратися й під wasm).
- Агент сам перевіряє результат, якщо інструмент є на машині: Godot headless, `npm run build`, `cargo build --release`.
- Хід роботи пишеться в журнал генерації й показується наживо.
- Генерацію можна зупинити.

### Рецепти білдів

| Рушії | Як збирається |
|---|---|
| Godot | `godot --export-release` з пресетами експорту, які додає студія |
| Unity | Unity `-batchmode -executeMethod` зі скриптом збірки студії |
| Unreal | `RunUAT BuildCookRun` |
| Three.js, Babylon.js, Phaser | `vite build` для Web; десктоп через оболонку Tauri; Android через Capacitor |
| Bevy, three-d, Penumbra | `cargo build --release` нативно; `trunk` для Web; `cargo apk` для Android |
| Defold | `bob.jar resolve build bundle` |

- Студія сама знаходить Godot, Unity, Unreal, JDK, Android SDK/NDK, Rust-таргети і `bob.jar`. Результат кешується на 30 секунд.
- Для кожної платформи показується готовність: що вже є і чого бракує. iOS потребує macOS з Xcode.
- Білди виконуються по черзі одним воркером, тайм-аут 3 год, лог зберігається у файл.
- **Виправити збірку**: останні 40 рядків логу падіння передаються агенту, і він виправляє код, щоб білд проходив.

### Плейтест

Стоїть між кодом гри й білдами: після автоматичної генерації коду білди стартують лише тоді, коли плейтест закінчився (успішно чи ні). Запускається й вручну — вузол «Плейтест» або картка «02 Плейтест» на сторінці «Збірка».

1. Студія кладе в гру бота: `noctics_playtest/bot.gd` і `override.cfg` з автозавантаженням `NocticsPlaytestBot` (наявний `override.cfg` зберігається й повертається). Сам `project.godot` не змінюється. Після плейтесту бот прибирається, а перед кожною генерацією коду й білдом студія ще раз перевіряє, що його немає.
2. `godot --headless --import`, потім гра у вікні 1280×720 без звуку: `godot --path <гра> --resolution 1280x720 --audio-driver Dummy -- --noctics-out=<папка> --noctics-seconds=40`. Без `--noctics-out` бот вимкнений.
3. Бот за 40 с: кадр меню; на 2,5 с тисне кнопку старту («Почати», «Грати», «Нова гра», Play, Start, оминаючи «Вихід» і «Налаштування») або `ui_accept`; далі по черзі тримає рухи й тисне дії гри з Input Map (крім паузи, меню й виходу), іноді клацає мишею в центр; кадр кожні 4 с; наприкінці `ui_cancel` двічі — пауза й повернення. Кожен кадр — PNG 1280×720 і JPEG-прев’ю 480 px; `manifest.json` дописується після кожного кадру: підпис, секунда, сцена, `blank` (кадр майже одного кольору), натиснуті дії, відкриті сцени, `finished`.
4. Помилки Godot (`SCRIPT ERROR`, `ERROR`, `Parse Error`, з рядком `at:`) збираються з виводу без повторів, до 20. Падіння, ненульовий код виходу й зависання теж записуються.
5. Claude-агент (ті самі інструменти, що й для коду) переглядає кадри через Read, порівнює з `screens/` і палітрою з `design.md`, виправляє код і сам перезапускає бота в `round-2`, `round-3` — до трьох прогонів. Звіт пише у `verdict.json`: `passed`, `fixed` або `needs_work`, підсумок і список проблем із позначкою «виправлено».
6. Фінальний прогін бота після виправлень. Якщо в ньому немає жодного кадру, вердикт стає `needs_work`.

Кадри показуються в інтерфейсі через asset-протокол Tauri (`http://asset.localhost/…`), папка запуску додається в його scope. Під час прогону інтерфейс оновлюється кожні 2 с, тож кадри з’являються наживо. Плейтест можна зупинити; поки він іде, генерація коду, підключення папки й білди цієї гри заблоковані.

### Режим «Вузли»

Друга версія фабрики: замість бічної панелі й сторінок уся гра — граф вузлів, з’єднаних кабелями. Перший режим лишається без змін.

```
┌ NOCTICS [Гра ▾]  ● Екрани гри  Малює «Меню паузи»  02:14   [Класичний|Вузли] ┐
│                                                                              │
│ [Промпт]─[План]─┬─[Референси]──┬─[Екрани]──[Код гри]─┬─[Ассети]─┬─[Білд …]  │
│                 └─[Навички 01]─┴─[Навички 02–05]─────┘          └─[Білд …]  │
│                                                                  інспектор   │
│ [− 80% + Вмістити Розкласти]  кольори кабелів                                │
└──────────────────────────────────────────────────────────────────────────────┘
```

| Вузол | Звідки дані | Дії в інспекторі |
|---|---|---|
| Промпт гри | промпт, рушій, платформи | новий проєкт (промпт, рушій, платформи), «Нова гра» |
| План гри | статус проєкту, назва, пітч, стиль, дизайн-документ | — |
| Референси | дошка проєкту, піни, стан Pinterest | підібрати заново, підтягнути піни |
| Навички етапу 01 / 02–05 | результати навичок за етапами | перегенерувати документ, синхронізувати навички |
| Екрани гри | екрани Claude Design з прев’ю | апрувнути, перегенерувати |
| Код гри | код гри, хід роботи агента | згенерувати, зупинити, відкрити папку |
| Плейтест | прогони бота, кадри, звіт Claude, помилки Godot | запустити, зіграти ще раз, зупинити, відкрити кадри |
| Ассети | задачі ComfyUI цієї гри, файли моделей | — |
| Анімації | замовлення Mixamo цієї гри з GIF-прев’ю | увійти в Mixamo, підібрати під гру, знайти й додати, ще раз, показати FBX, видалити |
| Пошук ассетів | знахідки з itch.io та інших сайтів, прев’ю, ліцензії | знайти ассети, шукати окремо за запитом, відкрити сторінку |
| Білд <платформа> | заплановані й зібрані платформи, готовність інструментів | зібрати, скасувати, виправити, показати файл, лог |

- Стан вузла — той самий, що в трекері етапів: Працює → Помилка → У черзі → Чекає на тебе → Готово → Очікує. Він видно з лампочки, обводки й смужки прогресу `готово/усього`.
- Кабель має колір даних, які несе: жовтий — тексти й документи, синій — стиль, референси й арт, сталевий — код, помаранчевий — білди. Білди беруть код через вузол «Плейтест», якщо він доступний для рушію, інакше — прямо з «Коду гри».
- Режим «Вузли» має власну палітру в кольорах Бетмена (токени `--nf-*` у `nodes.css`): майже чорне тло `#050506`, графітові вузли `#0f0f12`, акцент — жовтий бет-сигнал `#ffd21a` (головні кнопки з чорним текстом, обраний вузол, фокус), прожектор у «небі» полотна. Кабель, що веде у вузол, який зараз працює, світиться й біжить імпульсами.
- Рядок «Зараз» у верхній панелі показує найважливіший активний вузол і таймер; клік підводить до нього камеру.
- Полотно: перетягування лівою або середньою кнопкою — рух, колесо миші — масштаб навколо курсора (5–250 %), `Ctrl +`/`Ctrl −` — масштаб з будь-якого місця сторінки, `Ctrl 0` — 100 %, стрілки — зсув, `+`/`−`/`0` без Ctrl — те саме, коли фокус на полотні, `F` — показати весь граф (клавіші працюють за фізичною кнопкою, тож і на українській розкладці), `Esc` — закрити інспектор. Вузли перетягуються, розкладка зберігається локально (`noctics.node-layout`), «Розкласти» повертає початкову.
- Панель «Вузли» виїжджає знизу на всю ширину полотна; кнопка «Вузли N/M» стоїть першою в нижньому рядку, панель піднімає цей рядок над собою. На панелі всі вузли графа міні-картками з кольором і гніздами. Картку тягнеш на полотно, і вузол стає там, де відпустив. Вузол з полотна кидаєш на панель або на кнопку «Вузли», і він ховається разом зі своїми кабелями. Клік по схованій картці ставить вузол у центр, по видимій відкриває інспектор, `Delete` на картці ховає вузол, «Повернути всі» повертає сховані. Сховані вузли й стан панелі зберігаються локально (`noctics.node-tray`, `noctics.node-tray-open`).
- Поки камеру не рухали, вона тримає читабельний масштаб і стежить за вузлом, що працює.
- Кнопка внизу інспектора відкриває ту саму систему в класичному режимі.
- `BuildOverview.planned` — платформи, заплановані під час запуску гри; з них будуються вузли білдів.

## 17. Відомі обмеження

- Без встановленого й підключеного до підписки Claude Code студія не працює.
- Етапи 03–05 дають лише текстові специфікації. Для етапу 05 немає стартової навички.
- Розділ 3D Models відкриває зовнішні інструменти з тулбоксу. Задачі ComfyUI ставить агент збірки; якщо ComfyUI вимкнений, він лишає в грі слоти арту й промпти в art/prompts.md.
- Слоти арту на екранах Claude Design заповнюються лише в грі на етапі збірки, не в самому макеті.
- Звукові ефекти зараз роблять музичні моделі ACE-Step; для чистих SFX краще встановити Stable Audio Open — Noctics підхопить його автоматично.
- Для генерації коду не зберігається час старту, тому трекер не показує її таймер.
- Плейтест поки грає лише в ігри на Godot. Вікно гри відкривається на екрані двічі приблизно на 45 с (перший і фінальний прогін), плюс прогони, які запускає Claude.
- Бот натискає дії з Input Map і клацає мишею в центр екрана. Гру, яка читає клавіші напряму (`Input.is_key_pressed`), він не зрушить; Claude побачить це на кадрах як нерухомого персонажа.
- iOS збирається лише на macOS з Xcode.
